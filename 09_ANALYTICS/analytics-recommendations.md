# Analytics Recommendations — что нужно добавить в продукт

**Дата:** 2026-10-02 · **Статус:** 🟡 **НА СОГЛАСОВАНИИ У ОСНОВАТЕЛЯ.** Счётчик Метрики основатель создаст в воскресенье 2026-10-04 (интервью 1.10); остальной список ждёт подтверждения. В код **ничего не внедрено**. После подтверждения можно подготовить конкретные изменения для репозиториев продукта: их вносит разработка, а не эта сессия.
**Основание:** аудит сайта ([`../01_RESEARCH/site-audit-2026-10-02.md`](../01_RESEARCH/site-audit-2026-10-02.md), §8).

## 1. P0 — до запуска маркетинга

| # | Что | Как (для разработки) | Зачем |
|---|---|---|---|
| A-1 | **Создать счётчик Яндекс Метрики** и прописать ID в переменную окружения фронтенда, затем пересобрать | Основатель создаёт счётчик в metrika.yandex.ru; разработка прописывает ID в переменных окружения прода (`NEXT_PUBLIC_*` подставляются при сборке, так что нужна пересборка) | Без счётчика нет данных о трафике |
| A-2 | Включить вебвизор и карту кликов (уже в коде инициализации: `clickmap`, `trackLinks`, `accurateTrackBounce`) | Настройка в счётчике | Видеть, где люди теряются |
| A-3 | Проверить **cookie-баннер**: видимость и формулировки | Если большинство не нажимает «принять все», Метрика не видит большую часть трафика | Иначе данные смещены |

| A-5 | Подключить **Яндекс Вебмастер** | Основатель | Индексация, запросы |

## 3. Продуктовые метрики из базы (источник правды)

Метрика видит только тех, кто согласился на cookies, поэтому **ключевые метрики маркетплейса** нужно считать на стороне сервера. Рекомендация — еженедельный отчёт (SQL-запросы или страница в админке Filament):

| Отчёт | Поля |
|---|---|
| Пользователи | новые за неделю; по роли (есть объявления / есть заявки); город; источник (UTM, см. §4) |
| Объявления | новые, опубликованные, отклонённые (причины), активные — по категории × городу; доля с ≥4 фото |
| Заявки | новые, опубликованные — по категории × городу |
| **Ликвидность** | для каждой заявки: время публикации, время первого отклика, число откликов → fill rate за 2 ч, медиана времени до отклика |
| Контакты | показы телефона, новые чаты по объявлениям |
| Сделки | `deal-check` подтверждения; отзывы |
| Доверие | жалобы (на пользователей, объявления, отзывы); срабатывания антифрод-предупреждений |
| Деньги | новые и продлённые подписки по тарифам; поднятия; MRR |

## 4. Атрибуция (P1)

| # | Что | Зачем |
|---|---|---|
| A-6 | Сохранять **first-touch UTM** (`utm_source`, `utm_medium`, `utm_campaign`, `utm_content`) и `referrer` при первом визите (cookie или localStorage) и записывать в профиль пользователя при регистрации | CAC по каналам для владельцев и арендаторов; оценка блогеров и CPA |
| A-7 | Передавать `user_id` в Метрику (параметры посетителя) после входа | Связать веб-поведение с продуктовыми данными |
| A-8 | Единый словарь UTM (см. ниже) | Сопоставимость каналов |

**Словарь UTM:**
- `utm_source`: yandex, vk, tg, dzen, yt, partner, offline, influencer, email, telegram_bot
- `utm_medium`: cpc, clip, post, seed, qr, visit, influencer, crm
- `utm_campaign`: `<city>_<segment>_<goal>` (например, `nsk_spec_owners_supply`)
- `utm_content`: ID креатива или блогера (V020, INF-003)

## 5. Чего не делаем

- Не внедряем ничего в код из этой сессии.
- Не подключаем сторонние трекеры без согласия пользователей на cookies.
- Не передаём персональные данные (телефоны, e-mail) в Метрику.
