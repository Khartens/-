# CLAUDE.md — правила проекта Growth OS Машина.РФ

Этот файл читает Claude в начале каждой сессии. Здесь правила, по которым ведётся репозиторий. Источник правил — исходная инструкция основателя «МАШИНА.РФ — GROWTH OS» (этапы 0–22) и решения основателя D-01…D-16 в [`00_FOUNDATION/decision-log.md`](00_FOUNDATION/decision-log.md). Если правило здесь расходится с `decision-log.md` — верен `decision-log.md`.

## 1. Что это за репозиторий

- **Growth OS** проекта **Машина.РФ** (https://mashinarf.ru/) — площадки аренды транспорта и спецтехники напрямую у владельцев.
- Claude выступает как CMO и вся growth-команда: исследования, стратегия, контент, outbound, блогеры, CRM, аналитика, эксперименты, планы.
- GitHub — главное рабочее пространство. Результат работы — файлы в репозитории, а не ответы в чате.
- **Главная цель:** не презентация, а система, которая каждый день отвечает: что делать, зачем, для кого, как, сколько стоит, что измерять, когда остановить, когда масштабировать, что мы узнали.
- Карта репозитория для людей — [`ПУТЕВОДИТЕЛЬ.md`](ПУТЕВОДИТЕЛЬ.md). Главные документы: [`13_EXECUTION/30-day-plan.md`](13_EXECUTION/30-day-plan.md) и [`02_STRATEGY/master-growth-strategy.md`](02_STRATEGY/master-growth-strategy.md).

## 2. Жёсткие запреты (без исключений)

- **Не трогать продукт.** Никаких изменений в репозиториях `Khartens/laravel-machine` и `Khartens/next-machine`. Сайт, код, тестовые данные, e-mail, ЮKassa, Яндекс Метрика — зона основателя (D-14). Мы предлагаем, но не внедряем.
- **Аналитика:** события и цели в код не внедряем. Сначала рекомендации в [`09_ANALYTICS/analytics-recommendations.md`](09_ANALYTICS/analytics-recommendations.md), потом согласие основателя.
- Не удалять существующий код и документы. Устаревшее → [`99_ARCHIVE/`](99_ARCHIVE/) или пометка «устарело» со ссылкой на новое решение.
- Не трогать secrets, `.env`, ключи, токены, пароли, IP серверов. Не коммитить чувствительные данные.
- **Персональные данные** (телефоны, имена владельцев, переписки, контакты блогеров) — только в закрытых таблицах основателя, никогда в репозитории (152-ФЗ).
- Не придумывать ответы за основателя. Подтверждённые ответы в `founder-interview.md` не переписывать без согласия.
- Не выдумывать факты, цифры и цены. Вместо них — плейсхолдеры: `{…}` — факт основателя, `[цена]` — реальная цена владельца.
- Не менять архитектуру продукта без согласования. Маркетинговые материалы хранятся отдельно от production-кода.

## 5. Как писать документы

- Язык — **русский**, простой: основатель не технический специалист. Короткие предложения, без жаргона там, где можно обойтись.
- **Метки утверждений:** `FACT` (с источником), `HYPOTHESIS`, `UNKNOWN`, `SOURCE`, `FOUNDER INPUT`. В исследованиях дополнительно `FACT` / `INTERPRETATION` / `HYPOTHESIS` / `RECOMMENDATION`.
- **Источники** важных фактов — таблицей: `Source | URL | Date accessed | Claim | Confidence`. Общий реестр — `00_FOUNDATION/sources.md`.
- **Приоритеты:** P0 — критично, P1 — важно, P2 — желательно, P3 — потом. Не делать всё одновременно.
- У каждого эксперимента и теста — метрика, условие остановки и условие масштабирования.
- У документа — дата и версия в шапке; при значимой правке — строка в журнале версий.

## 6. Контент и графика

**Тексты:**
- Минимализм, как на сайте: коротко, одна мысль в предложении, без эмодзи и восклицаний.
- **Города не называем** (D-16), в том числе в хештегах. Можно противопоставлять «большой город — небольшой город» без названий.
- Рилс: сначала **хук** (цифра, конфликт, неожиданность), потом история основателя, потом площадка. Без прямой рекламы в самом ролике.
- **Instagram:** никакой рекламы (72-ФЗ) — без цен, ссылок, призывов и промокодов. Общее правило для всех сценариев — в шапке `ready-scripts.md`; особые случаи отмечены в самих сценариях.
- Ролики «Деньги» и «Цены» — только с реальными цифрами владельцев.

**Графика** (`03_CONTENT/assets/`, подробно — [`assets/README.md`](03_CONTENT/assets/README.md)):
- Стиль шапки сайта: белый фон, тёмно-синий `#102e7a`, текст `#0f172a`, серый `#64748b`, золотой акцент `#d4af37` (тонкая линия), Inter.
- Логотип — «М»-лента + «Машина.РФ» (Montserrat), по образцу основателя. Без капса, без красного, без градиентов.
- **Ровно 2 строки текста** на картинке: первая тёмная, вторая синяя, каждая целиком в одну строку; на обложках ~96 px (не меньше ~80).
- Обложка рилса = номер сценария: `covers/S13.jpg` ↔ сценарий S13 в `ready-scripts.md`.
- Картинки не рисуются вручную: правим тексты в `03_CONTENT/assets/_generator/` и пересобираем (`build_covers.py`, `build_rest.py`). После сборки — посмотреть результат глазами.

## 7. Outbound и блогеры — закон и площадки

- Без спама и массовых рассылок. Звоним по публичным рабочим номерам, индивидуально; отказ — в стоп-лист (38-ФЗ ст. 18).
- Не пишем владельцам в чаты Авито и других площадок с предложением уйти к нам: правила площадок это запрещают.
- Любая интеграция у блогера, даже бартер, — реклама: маркировка (ERID, ОРД); у блогеров с аудиторией 10 000+ — проверка в реестре РКН.
- Правила — [`05_OUTBOUND/README.md`](05_OUTBOUND/README.md), [`04_INFLUENCERS/influencer-playbook.md`](04_INFLUENCERS/influencer-playbook.md).

## 8. Как вносить изменения (GitHub-дисциплина)

Для каждой значимой группы изменений:
1. Коротко показать план.
2. Создать или изменить файлы.
3. Проверить структуру, ссылки и markdown (раздел 9).
4. Убедиться, что ничего существующего не сломано.
5. Показать список изменённых файлов и объяснить, что изменилось.

**Коммиты:**
- Префиксы: `growth:` (структура, планы, система), `research:`, `strategy:`, `content:`, `analytics:`.
- Несвязанные изменения — разными коммитами.
- Pull request — только если основатель попросил.

**Как обновлять систему:**
- Новый ответ основателя → `founder-interview.md`; новое решение → `decision-log.md`.
- Изменился факт о продукте → `project-brief.md`.
- Каждую неделю — growth loop в `weekly.md`: DATA → ANALYSIS → LEARNING → HYPOTHESIS → EXPERIMENT → RESULT → NEXT EXPERIMENT; выводы — в `10_EXPERIMENTS/learnings.md`.
- `13_EXECUTION/30-day-plan.md` правится напрямую.

## 9. Проверки перед коммитом

```bash
# 1. Битые ссылки в markdown (относительные пути должны существовать)
python3 - <<'PY'
import re,os,subprocess
bad=[]
for p in subprocess.check_output(['git','-c','core.quotepath=off','ls-files','*.md']).decode().split():
    d=os.path.dirname(p)
    for l in re.findall(r'\]\(([^)#\s]+)',open(p).read()):
        if not l.startswith('http') and not os.path.exists(os.path.normpath(os.path.join(d,l))): bad.append((p,l))
print(bad or 'ссылки ок')
PY
# 2. Города в публичных материалах (должно быть пусто)
grep -nE "Москв|Питер|Петербург|СПб|Барнаул|Алта|Дагестан" 03_CONTENT/ready-*.md 03_CONTENT/easy-reels-playbook.md 03_CONTENT/assets/_generator/*.py
# 3. Телефоны и ключи (должно быть пусто)
git grep -nIE '\+7[ -]?\(?9[0-9]{2}|(api[_-]?key|secret|password|token)\s*[:=]\s*[A-Za-z0-9]{8,}'
```

Также проверить: в таблицах одинаковое число колонок; все файлы, на которые ссылаются планы (`covers/…`, `posts/…`, `cards/…`), существуют.
