# Машина.РФ — Growth OS

Рабочее пространство роста проекта **Машина.РФ** (https://mashinarf.ru/).
Здесь живёт вся growth-система: факты о продукте, интервью с основателем, исследования, стратегия, контент, каналы, эксперименты, метрики и ежедневное исполнение.

> ⚠️ **Этот репозиторий сейчас публичный** (проверено 2026-09-28). Всё, что сюда попадает — стратегия, ответы основателя, цифры, контакты партнёров — видно конкурентам и поисковикам. Рекомендация: сделать репозиторий приватным **до** того, как сюда попадут реальные метрики и ответы интервью. Секреты, пароли, ключи, IP-адреса серверов и персональные данные людей сюда не пишутся никогда — ни в публичном, ни в приватном режиме.

## Зачем этот репозиторий

Не презентация, а операционная система роста. Она должна в любой день отвечать на вопросы:

| Вопрос | Где ответ |
|---|---|
| Что делать сегодня / на неделе / в месяце? | [`13_EXECUTION/`](13_EXECUTION/) |
| Зачем и для кого? | [`02_STRATEGY/`](02_STRATEGY/), [`01_RESEARCH/audience/`](01_RESEARCH/audience/) |
| Как? | папки каналов `03`–`08`, `11`, `12` |
| Сколько стоит, что измерять? | карточки экспериментов в [`10_EXPERIMENTS/`](10_EXPERIMENTS/), метрики в [`09_ANALYTICS/`](09_ANALYTICS/) |
| Когда остановить / масштабировать? | stop/scale условия в каждой карточке эксперимента и теста |
| Что мы узнали? | раздел Learnings в [`10_EXPERIMENTS/`](10_EXPERIMENTS/) и еженедельные обзоры в [`13_EXECUTION/`](13_EXECUTION/) |

Продуктовый код (бэкенд и фронтенд) живёт в **отдельных** репозиториях. Здесь — только маркетинговые и аналитические материалы; production-код отсюда не меняется.

## Правила системы

### Маркировка утверждений

Каждое содержательное утверждение помечается:

| Метка | Значение |
|---|---|
| `FACT` | Подтверждено источником или кодом/данными. Всегда со ссылкой на источник |
| `FOUNDER INPUT` | Получено от основателя в интервью. Ссылка на раунд/вопрос |
| `SOURCE` | Взято из внешнего источника (URL, дата доступа) |
| `HYPOTHESIS` | Предположение. Требует проверки, указано, как проверить |
| `UNKNOWN` | Неизвестно. Ничего не придумываем |

В research-документах дополнительно разделяем `FACT` / `INTERPRETATION` / `HYPOTHESIS` / `RECOMMENDATION` и для каждого важного факта указываем `Source · URL · Date accessed · Claim · Confidence`.

### Приоритеты

- **P0** — критично, блокирует рост или создаёт риск
- **P1** — важно, делаем в ближайшем цикле
- **P2** — желательно
- **P3** — потом

### Коммиты

Префиксы: `growth:` (структура, система), `research:`, `strategy:`, `content:`, `analytics:`. Несвязанные изменения — разными коммитами.

### Как обновлять систему

1. Новая информация от основателя → `00_FOUNDATION/founder-interview.md` (подтверждённые ответы не переписываются без согласия основателя; уточнения добавляются ниже с датой).
2. Изменился факт о продукте → `00_FOUNDATION/project-brief.md` + строка в «Журнале изменений» брифа.
3. Новый источник → `00_FOUNDATION/sources.md`.
4. Каждую неделю → growth loop: **DATA → ANALYSIS → LEARNING → HYPOTHESIS → EXPERIMENT → RESULT → NEXT EXPERIMENT** (описание появится в `13_EXECUTION/`).
5. Документ устарел → переносим в `99_ARCHIVE/` с датой в имени, а не удаляем.

## Безопасность

- Никаких секретов, `.env`, токенов, паролей, IP серверов, SSH-данных.
- Персональные данные (телефоны, e-mail реальных владельцев/клиентов) — не хранить в репозитории; в CRM-шаблонах только поля и обезличенные примеры.
- Production-код и архитектура продукта меняются только в продуктовых репозиториях и только после согласования с основателем.
